# Product Factory — Operating Charter v0.1

**Date:** 2026-10-06  
**Status:** WORKING

## 1. Objective

Create a portfolio of small digital products that can be sold globally through multiple independent channels.

We aim to become the product owner / supplier rather than primarily a reseller:

`Product/IP → version → license/entitlement → distribution channel → customer`

Possible commercial units:
- one-time license
- per-use / per-run
- credits
- subscription
- API usage
- team plan
- agency plan
- white-label
- enterprise deployment

A "license inventory" means digital entitlement capacity, not physical inventory.

## 2. Portfolio strategy

The initial portfolio contains nine deliberately different hypotheses. Each receives only enough engineering to become a real testable offer.

No large architecture investment is justified before evidence.

## 3. Pilot design rule

Each pilot starts with:

`Pain → one input → one transformation → one valuable output → payment → delivery`

Avoid premature:
- large dashboards
- broad platforms
- speculative integrations
- complex RBAC/SSO
- generic AI chat
- elaborate infrastructure

## 4. Decision gates

Every pilot is evaluated on:

1. problem clarity
2. time-to-value
3. usefulness of output
4. willingness to pay
5. repeat usage / retention
6. acquisition channel
7. contribution margin
8. distribution surface area
9. defensibility
10. build + support burden

Negative evidence is first-class. A product may be killed without being "rescued" by changing the success criteria after results arrive.

## 5. Evidence vocabulary

Use these labels for material claims/results:

- ESTABLISHED
- EXPERIMENTALLY_SUPPORTED
- USER_REPORTED
- INFERENCE
- HYPOTHESIS
- CONTRADICTED
- UNKNOWN
- OPEN

Each experiment records:
- hypothesis
- input/sample
- method
- environment/version
- outputs/artifacts
- failures
- negative evidence
- decision
- next discriminating test
